## 二、装备"结余（红/绿）"口径的推导过程（重要）

1. 「后勤」窗口那一列是**净储备**（可负=缺口）；
2. 用户实测截图里的悬浮提示把两个数分开显示：
   - 18:06 轻型坦克：储备 **-700**，陆军师携援 **-1000** → 差 **+300**（=库存）
   - 18:54 轻型坦克：储备 **-223**，陆军师携援 **-223** → 差 **0**
3. 由此得到：**储备 = 携援 + 库存 = (已装备 − 需要) + `num_equipment@大类`**；
4. 验证：19:02:23 同屏截图，「后勤」步兵装备 `资源 = -18.4K`（悬停：储备 -18.43K / 携援 -18437），我们格子 = **-18555** → 吻合（差≈0.7%，属于数值每天变化造成的漂移）。

实现位置：`dui_topbar/common/scripted_localisation/dui_topbar_scripted_loc.txt` 里 12 个 `GetDUIEquipBal_*`：
每个 `defined_text` 两个分支（`dui_bal < 0` → `DUI_BAL_NEG` 红；否则 `DUI_BAL_POS` 绿），
格子文本与悬停提示都读同一个 `defined_text`，因此不会出现"两处数字不一致"。

## 三、明确不可用 / 有限制

| 需求 | 结论 | 依据 |
| --- | --- | --- |
| 直接读引擎的净储备 | **没有可读变量** | 界面数值由引擎填入具名元素与 loc 参数：`interface/countrylogisticsview.gui`（`needs`/`in_need`）、`localisation/english/logistics_l_english.yml:13/75`（`$INSTOCK$`） |
| 产量 / 消耗（自建账本需要的输入） | **没有可读接口** | 在原版+黑冰全库搜索 `num_equipment_produced` / `equipment_production` / `num_produced_equipment` / `equipment_surplus` / `equipment_deficit` / `num_equipment_needed` / `num_equipment_missing` / `equipment_consumption` 均 0 命中 |
| 只判断"有没有缺口" | 可以（布尔） | 原版 `has_equipment = { infantry_equipment < 0 }`（`common/decisions/CHI.txt:154`） |
| 脚本里读 `num_equipment@大类` | **只在"脚本化本地化 + set_temp_variable"这条路有效** | loc 文本里直接 `[?num_equipment@…]`、效果里 `set_temp_variable`、每日快照里读，实测都拿不到（显示 0） |
