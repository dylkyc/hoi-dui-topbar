# 问题与解决（按发生顺序，含证据）

> 结论原则：**先看 `logs/error.log`、先查原版/黑冰出处，再改代码**；没有证据的结论一律标"推测"。

## A. 让游戏崩溃 / 整块失效的问题

| # | 现象 | 根因 | 解决 | 证据 |
| --- | --- | --- | --- | --- |
| A1 | 进游戏闪退 | 自制 DDS 头写错（`dwSize` 与字段错位） | 放弃自制贴图，改用现成贴图 | 当时 error.log 的 `gfx_dds_loader.cpp:325 Expected more data in the texture mipmaps` |
| A2 | 图标全部不显示 | 生成的 `.gfx` 带 **UTF-8 BOM** | `.gfx` 一律 ASCII/无 BOM；`.yml` 必须带 BOM | `Unexpected token: spriteTypes, near line: 1 in file: interface/dui_icons.gfx` |
| A3 | 菜单整个不加载（点格子没反应、下拉不出现） | `interface/dui_topbar.gui` 被改坏：元素被塞进别的元素内部、`}` 与 `name =` 挤在同一行 | 用**逐行手术**重写该段；此后加"粘连行"检查 | `Error: "Unexpected token: instantTextBoxType, near line: 470" in file: interface/dui_topbar.gui near line: 479` |
| A4 | 自检脚本自己报语法错 | 无 BOM 的 `.ps1` 里写了中文注释，Windows PowerShell 按 ANSI 解码 | 脚本内注释只用 ASCII | `check_vars.ps1` 第 28 行 `"modifier",` 报 `缺少表达式` |
| A5 | `buttonType` 报 `Malformed token: width/height` | 按钮不能写 `size`（容器才能写） | 按钮不写 size，由容器决定尺寸 | error.log 9 次同类报错 |

## B. 脚本逻辑问题

| # | 现象 | 根因 | 解决 |
| --- | --- | --- | --- |
| B1 | **绑定写到别的格子**（点"右5"的菜单，值进了"右1"） | 绑定只认全局 `dui_selected`，它会漂移/被清 | 每个格子点击时写 `dui_target`（16 处），绑定前 `set_variable = { dui_selected = dui_target }` |
| B2 | 点「装备库存」要连点 2~3 次才展开 | 用 `check_variable = { dui_menu_v = token:dui_m_equipment }` 比较 token，不可靠 | 改用黑冰写法 `is_in_array = { dui_subcategory = dui_menu_v }`（配合 `dui_subcategory` 数组 + `dui_subcategory_selected`） |
| B3 | 点按钮"无反应"（列表其实换了但界面不动） | 刷新标志写成 `set_variable = { dui_menu_dirty = 1 }`（重复设同值 = 不重绘） | 改为 `add_to_variable = { dui_menu_dirty = 1 }`（递增；与已能用的 `dui_topbar_open_menu` 一致） |
| B4 | 「装备库存」条目在菜单里消失 | 该条目被加进 `dui_topbar_init`，而每次开菜单会 `clear_array` 重建主列表 | 移到 `dui_topbar_open_menu`（`dui_topbar_effects.txt:122-125`） |
| B5 | 效果名重复 / 两条语句挤在一行 | 批量脚本替换时丢了换行、重复插入 | 改完**从磁盘回读**核对；自检脚本加"粘连行"检查 |
| B6 | 「日切后 UI 不更新」 | 数值走"每日快照写变量"这条路 | 改为在**脚本化本地化里实时求值**（每次渲染重新取数），天然随时间变化 |
| B7 | 菜单里多出一个常显小窗口，遮挡按钮、不能拖动 | 用元素级触发器 `dui_sub_panel_visible` 控制显隐，**该机制没生效** | 先移除面板（恢复"替换主列表"方案）；要做真正的浮层需先查明元素级触发器写法 |

## C. 数值接口问题（最容易出错的一类）

| # | 现象 | 过程与结论 |
| --- | --- | --- |
| C1 | 12 个装备大类全显示 0 | 依次试过：loc 里直接 `[?num_equipment@…]` ✗ / 带 `ROOT.` ✗ / 脚本化 GUI 点击效果里读 ✗ / `on_daily + every_country` 里读 ✗；最后**照黑冰在脚本化本地化里 `set_temp_variable` 再输出**才拿到值 ✓（`BI_AI_scripted_loc.txt:543-558`） |
| C2 | 数值与原版「后勤」对不上 | 1) 早期比的是**不同时刻**的截图（数值每天变）✗；2) 公式少/多项。最终口径：**结余 =（已装备 − 部队需要）+ 库存** = `num_equipment_in_armies@大类 − num_target_equipment_in_armies@大类 + num_equipment@大类` |
| C3 | 「后勤」那个负数到底是什么 | 「后勤」`资源` 列是引擎算的**净储备**（可含缺口）；界面里的 `needs` / `$INSTOCK$` 都是**引擎直接填的**（`interface/countrylogisticsview.gui`、`logistics_l_english.yml:13/75`），脚本不能直接读 → 只能用 C2 的三项复现 |
| C4 | 判断装备是否短缺 | 原版用 `has_equipment = { infantry_equipment < 0 }`（`common/decisions/CHI.txt:154`）→ 是**触发器**、只能给布尔；若日后需要"有/无缺口"状态可用它 |

## D. 流程/协作类问题（教训）

| # | 现象 | 解决 |
| --- | --- | --- |
| D1 | 「改了却看不到变化」两轮 | 复制没带上改动文件。此后**每轮复制后用 MD5 或 `Select-String` 自证**（把证据贴给对方） |
| D2 | 把"推测"当结论汇报 | 现在明确区分：**验证过的事实**（附出处）／**推测**（明确标注）；没证据就说"没有找到可读接口" |
| D3 | 拿不同时刻的数字对比 | 必须**同屏截图**（后勤 + 我们的格子）或同一画面内对比 |
| D4 | 只看日志不看截图 | 截图能发现日志发现不了的问题（元素错位、被遮挡、图标错配、数值截断） |
| D5 | 用 K/M 缩写导致读数不全 | 测试期不缩写、悬停提示显示完整数字（提示框没有宽度限制） |
